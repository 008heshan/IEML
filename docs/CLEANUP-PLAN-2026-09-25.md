## 二之二、★★ CurseForge 那把 key 的最终处置：**不内置，也能开箱即用**

**用户的要求是硬的**：「开箱即用是对的，我们不希望让用户去填，因为用户根本就不会」
—— 所以"删掉内置 key、让用户自己申请"**不是**可选项。但仓库要公开，内置凭据又必须消失。

**解法（实测得到，不是设计推断）**：默认走**国内镜像** `mod.mcimirror.top`，那条路**不需要任何 key**。
探针 `tools/probe/probe-cf-mirror-keyless.mjs`（**不带任何 `x-api-key`**）实测 5/5 可用：

| 接口 | 不带 key 的结果 |
|---|---|
| GET 搜索（热门 / 关键词） | 200 · `totalCount=10000`，数据完整 |
| GET 文件列表（版本） | 200 · JEI `totalCount=3757` |
| GET 单个项目详情 | 200 · 字段齐全 |
| GET 分类 | 200 · 148 条 |
| **POST 指纹反查**（"检查更新"那条路） | 200 · `exactMatches` / `unmatchedFingerprints` 形状一致 |

而 `mirror.rs` 早就把 CurseForge 排成"**国内 mcimirror 首选、官方兜底**"了 ——
所以这次不是发明新路，而是把**已经在跑的默认路**上那把多余的 key 摘掉。

**现在的传输规则**（`net/curseforge.rs` 的 `Route`）：

```
没有自备 key（默认，绝大多数用户） → 走镜像，不带 key   ← 开箱即用
自备了 key（设置页 / IEML_CF_API_KEY） → 走官方，带上它；官方不通再退镜像
```

### ★★ 顺手修掉一个**一直存在、没有任何判据能发现**的真缺陷

指纹反查的请求体在两条路上**形状正好相反**（两个方向都实测过）：

| 发给谁 | 正确形状 | 发错的后果 |
|---|---|---|
| 官方 | `{"fingerprints":[123]}`（**裸整数**） | 对象数组 → 400 `The JSON value could not be converted to System.UInt32` |
| 镜像 | `{"fingerprints":[{"fingerprint":123}]}`（**对象数组**） | 裸整数 → 400 `invalid type: map, expected i64` |

旧代码**兜底时复用的是官方那份 body** ⇒ **"官方不通就换镜像"这条兜底 100% 返回 400**。
也就是说："Mod 检查更新"在官方连不上时**必然失败**，而这台机器上官方**本来就经常连不上**
（`live_curseforge` 实测超时）—— 用户看到的就是"查不到更新"。

修法 & 防复发：
* `api_post_json` 收两份 body（主路一份、兜底一份）；
* 新增契约测试 `fingerprint_request_bodies_have_the_two_measured_shapes`
  —— 它**当场抓出我自己写错两次**（写成 `fingerprints: &[u32]` 时两条路序列化结果一模一样，等于没换）；
* 探针里加了反向对照（给镜像发裸整数，预期 400），把"形状相反"这件事留在可重跑的判据里。

### 关于"把 key 放到自己的转发服务里"（方案 B，用户选"稍后再说"）

这是更可控的形态：key 只存在**服务端**（环境变量），客户端只知道转发地址；
转发层还能限流、缓存、只放行需要的接口。**这次不做**，但客户端已经为它留好了位置：
`Route` 里加一条 `OwnRelay` 即可，其余不用动。

### ★ 一个"想过但决定不做"的判据：混合行尾硬门禁

`git diff --numstat` 与 `--ignore-cr-at-eol` 不一致 = 有纯空白噪声 —— 这条判据很准，
但做成**硬门禁**会逼着一次**上千行的全文件重写**（`DownloadPage.tsx` 有 1195 行 CRLF），
而那正是这类判据想防的"无关改动"。所以：
**保留判据但不进门禁** —— 改动那几个文件时按字节处理，`git diff --numstat` 自查（写在这里，供下次用）。

### ★ 另一个教训：pickaxe 会命中"提到 key 的文档"

重写后 `git log --all -S '<key 前缀>'` 仍报 1 个提交，一度看起来像没清干净。
查下来是**我自己写进本文件的验证命令**（文档正文里提到了那个前缀）被 pickaxe 命中了 ——
**不是泄露**。⇒ 审计判据要用**更硬的两条**：逐个 blob 全扫 + 逐条提交信息（`%B`）扫，
别只看 pickaxe 的计数（它同时受"文档里提到过"影响）。

### 我这次自己踩的坑（写下来免得复述错）

* **报"某文件某行写了 X"之前必须回读那一行** —— 我曾报告"`CHANGELOG.md:40` 把拖拽当入口"，
  而原文里**没有这句话**（照着工具给的行号下的结论）。
* **门禁自己的算法也会错**：锚点自检第一版把"空格"写成 JS 的 `\s`（**含全角空格**），
  而 GitHub 用的判据不含它 ⇒ 把 12 个**正确**的链接判成死锚点。红了先怀疑量法。
* **形状类的契约要靠测试守**：指纹的 body 形状我写错两次，都是被那条契约测试当场抓住的。
* ★★ **`git update-index --cacheinfo` 要三个参数**（`<mode>,<sha1>,<path>`）：
  我第一版写成 `… | xargs git update-index --cacheinfo` —— 只喂了 sha1、还丢了路径，
  于是过滤器**静默不生效**（报 `option 'cacheinfo' expects …` 而 `filter-branch` 照常往下跑）。
* ★★ **带注解的标签要多一步**：`filter-branch` 不会自动重写 `tag` 对象，
  得加 `--tag-name-filter cat`；否则**旧标签仍指着旧历史**、key 通过它依然可达
  （我第一次为了消警告去掉了那个开关，差点留下这个洞）。
  验证时必须看**所有引用**（`git rev-list --all`），只看 `HEAD` 会漏。
