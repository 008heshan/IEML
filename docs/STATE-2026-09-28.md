## 二、现在的骨架（读代码的入口）

### 2.1 分层

```
main.tsx ── 首屏前挂类（low-perf / data-motion / data-vfx）+ 注入 --ambient-image
  └ AppProvider（state/AppContext）   全局唯一状态机 + 唯一 I/O 与副作用中枢 + 事件总线
      └ ConfirmProvider（ui/confirm） 替代这个壳里坏掉的 window.confirm
          └ App（app/AppShell）       标题栏 / 侧栏 / 内容区 / 常驻弹窗
              ├ pages/       一页一文件、无 props（无路由库，条件渲染）
              ├ components/  领域组件（跨页复用、可直接调后端）
              ├ flows/       多步编排（安装 / 隔离切换 / 资源安装）
              ├ hooks/       useRealApi / useJavaRequirement / useLauncherUpdate
              ├ domain/      纯函数规则引擎（22 模块 + barrel，不许有 I/O）
              ├ state/       store.ts 纯 reducer（不知道后端）
              └ bridge/      一个 Backend 接口，两套实现（web.ts / tauri.ts）
```

Rust 侧：

```
main.rs → lib.rs::run()
   ├ commands.rs（24 条：规则壳）      ├ commands_real.rs（84 条：真实网络/安装/启动）
   ├ domain/*（19 模块，纯规则零 I/O） ├ net/*（10）+ modrinth + auth + modloader
   └ platform.rs（AppPaths / Java / 迁移）└ launch.rs / backup.rs / draft.rs / game/*
```

### 2.2 命令注册入口（唯一一处）

`src-tauri/src/lib.rs` 的 `tauri::generate_handler![…]`：**定义 108 条 = 注册 108 条**，
已逐名双向比对（无遗漏、无多注册）。加命令只改这一处。

### 2.3 数据布局（`AppPaths`，`src-tauri/src/platform.rs`）

```
<root>/                       用户选的游戏根目录（只放游戏的东西）
├── .minecraft/               = AppPaths.shared（共享 libraries / assets / versions）
└── instances/<slug>/
    └── game/                 = instance_game_dir（物理游戏目录）

<own_root>/                   启动器自己的家（默认避开系统盘）
├── instances.json  prefs.json  ms_client_id.txt
├── java/  cache/  logs/
└── backups/<slug>/<epoch 秒>/
```

两条**必须记住**的方法：

* `AppPaths::game_dir_of(slug)` = "这个实例**实际**用哪个游戏目录"（先做隔离判定）。
  凡是游戏会读写的东西（saves / mods / config / 资源包 / 数据包 / 备份）都必须走它。
* `instance_game_dir(slug)` 只是**物理目录**，只给 `natives/`、实例日志、备份清单用。

选址记录（`%APPDATA%\IEML\datadir.txt` 与 `ownroot.txt`）**必须放在被它决定的目录之外** ——
放进里面就是循环依赖，搬一次就再也找不回来。

### 2.4 三个"源"的概念别混（最容易看错的地方）

## 三、这一段（rc.11 → 0.18.0）新立的规矩

> 旧规矩见 `.workbuddy/memory/MEMORY.md`；下面只写这一段新增或改口径的。

1. **「以当前启动器为准」**：两处文档与代码冲突时，"实现怎么做，话就怎么说"。
2. **`1.0.0` 之后的版本号走法**：小修 `1.0.x` / 大修 `1.x.0` / 下一个大版本 `x.0.0`；
   **只许动一位、低位归零、位数不封顶、不许补零跳号**。由 `tools/gates/check-version-scheme.mjs` 守。
3. **更新日志第 ④⑤⑥ 条**：不写归属、**不写实现细节**（命令名/测试文件名/判据条数/退出码/路径）、
   整版没有玩家看得见的变化就合为一条「修改了 若干启动器底层事项」。
   ★ 第 ⑤ 条**对 `CHANGELOG.md` 最新那一节同样成立** —— 发布脚本把那一节原文当 `notes` 推给玩家。
4. **探针不打扰用户**：有实例在跑就退出码 2；网络不通时以"本次测量无效"退出，
   不把环境问题报成功能红。
5. **`APPDATA` 不只是"会被读"，还会被写**：`datadir.txt` 被写成仓库根那次，
   后果是"用户下次打开启动器会去仓库目录里找游戏"。
   ⇒ `tools/live/lib/cdp.mjs` 的 `launch()` 见到 `IEML_DATA_DIR`/`IEML_OWN_DIR` 就
   **自动把 `APPDATA` 也指进沙盒**；纪律：**探针一律走 `launch()`，不要自己 `spawn`**。
6. **"没测到"不是"通过"**；**对照组是判据的一部分**（没有它，主判据可以永远绿）。
7. **"用户选的是什么"与"实际生效的是什么"必须分开**。这一段里"说了不算"出现了三次，
   最后一次的规矩是：**照用户的选择用 + 一句警告，绝不偷偷回退**。
8. **声明了就必须在盘上**（版本描述里写了某个库，磁盘上就得有那个文件）。
9. **复制只有一条路**：只复制不删源、永不覆盖、可先备份。冗余的第二份实现被删掉了，
   理由写着"留着它，下一个写'搬一堆文件'的人很可能顺手拿去用"。
10. **`AppState.paths` 这类"全局单例变可替换"，风险永远是"谁还缓存着旧路径"** ——
    门禁 `cargo check --tests` 正是为此存在的。
11. **CI 的退出码不许被管道吃掉**（`.cnb.yml` 用"先落盘再 `exit $code`"，不用 `| tee`）。
12. **ADR 归档法**：⛔"不适用"与 ⏳"没做"分开写，并注明"谁改了前提谁补"。

## 四、这一段抓到的硬伤（都已修，留着当形状记忆）

* **CF 整合包永远只有一页**：`CfPagination` 少了 `rename_all = "camelCase"` ⇒
  `pageSize`/`resultCount`/`totalCount` 全是 0。**跨 IPC 字段名**这类错第 4 次发生，
  编译器看不见（都是 u64）。判据：`cf_pagination_field_names_match_the_api`。
* **沙盒的第三、四次事故**：`APPDATA` 被探针**写坏**；`0.15.0` 那次四条红**全是量法错**
  （选择器不存在、沙盒漏 `APPDATA`、合成实例撞一对一认领、在半渲染页面上判）。
* **整合包每段换新令牌** ⇒ 中间段点的暂停/取消被**悄悄丢掉**。
* **`install()` 把 `paused`/`remaining` 扔掉照样返回 `Ok`** ⇒ 报"安装成功 100%"而一个字节没下。
* **`library_is_wanted` 曾有两个实现** ⇒ 一边报"22 个库缺失"、一边一个库都没下。
* **OptiFine 的 jar 里带着 `META-INF/mods.toml`**（`modLoader="javafml"`）⇒ 被 Forge 当第二个
  Mod 再加载一次 ⇒ 启动冲突。删它**有前提**（只在那两种装法下动，其余一个字节不许改）。
* **旧注释比没有注释更危险**：多处明确写了"旧注释是错的"（Prism id 的说法、
  `detect_installed_loaders` 的"前端都会调它"、`loader_caps` 的"install_version 里有 Patcher 分支"）。
  读注释必须看日期与"更正"标记。

## 七、开工前该做的三件事

1. `node tools/verify.mjs`（**必须先把 `pnpm` 与 `cargo` 放进 PATH**）——
   它是"现在到底有什么门禁"的唯一权威，35 项里项数不写死、脚本自己打印。
2. 动前端 ⇒ 必须重跑一次完整 `tauri build`（exe 里嵌的是编译时的 `dist`），
   否则「exe 内嵌前端一致性」必红 —— 那是**设计如此**，不是误报。
3. 改任何"从接口数据得出什么结论"的代码 ⇒ 想一下 `metadata::CACHE_VERSION`
   要不要 +1，以及前端 `loader-catalog.ts` 的缓存 KEY 要不要同步。
   磁盘缓存里存的是**结论**不是原始 JSON —— 这是全项目最容易造成
   "我修好了但用户看不到"的机制。
