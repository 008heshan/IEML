## 关键路径判断

**M1 是架构验证点。** 它一旦跑通，就证明整条链（元数据解析 → 并发下载 → 参数拼装 → 进程管理）是成立的，后续都是增量。如果 M1 卡住，问题必然在架构层，越早暴露越好。

**M1.5 是体验分水岭。** 它决定产品是「能用」还是「好用」。之所以紧跟在 M1 之后，是因为它依赖的核心能力（元数据、加载器查询、安装流水线）在 M1 中已经具备——此时实现成本最低，且能立刻拿到用户反馈。

**为什么 M1.5 不拖到后面做**：单页安装不是"皮肤"，它是把已有能力重新组织成用户能理解的形式。如果等到 M4/M5 才做，会发现加载器查询、InstallPlan 这些底层接口需要返工。**先定交互，再填能力。**

## 每个阶段的验收动作

1. **三平台都能构建通过** —— 不要等最后才发现某个平台挂了
2. **体积没有明显膨胀** —— 每引入新依赖后检查二进制大小
3. **核心流程有集成测试** —— 尤其是版本安装和参数拼装这两个最容易出错的地方

## 待确认事项

进入 M0 之前需要定下来：

- [ ] 数据目录默认位置是否支持自定义（建议：支持，默认走系统标准目录）
- [ ] 是否内置 BMCLAPI 镜像作为默认下载源（**已有答案**：是。PCL2 `ToolDownloadVersion` 支持 0=优先镜像 / 1=先官方；HMCL 也用镜像表。见 ADR-026）
- [x] CurseForge API Key 获取方式（**已关闭 · 2026-09-26**：用户定「cf 完全不用 key」——
      全部走国内镜像 `mod.mcimirror.top`，启动器里没有 key 这回事，所以"渠道"这个问题不存在了。
      ★ 它当初担心的"可能成为发布阻碍"没有发生；代价改成"这一路依赖那个第三方镜像"，
      已写进 README 的「已知限制」）
- [ ] macOS 代码签名与公证证书准备（发布前必须，否则用户无法打开）
- [ ] 是否需要支持导入其他启动器（PCL / HMCL / 官方）数据（建议：支持，这是 Prism 的长板）
- [ ] OptiFine 无官方 API，选择「解析版本页」还是「仅支持手动填版本号」（**参考**：PCL2 是正则抓 optifine.net/downloads 的 `colForge` 列，这条路可行但有维护成本）
- [ ] 中文别名词表的来源：复用开源词表 vs 自建（影响初期体验）
- [ ] 备份的默认保留份数与触发时机（建议：保留 5 份，启动游戏前触发）
- [ ] **Draft 事务的回滚目录放哪**（HMCL 放在 `<baseDir>/.hmcl/repository-drafts/`，我们要不要对齐）
- [ ] **整合包导出黑名单要不要扩到「光影包配置」**（HMCL 把 `optionsof.txt` 放进了 suggested 黑名单，但它属于「可保留」的灰区）

## 已确认的关键决策

完整的决策记录见 [`DECISIONS.md`](./DECISIONS.md)。以下是与本路线图直接相关的几条：

| 编号 | 决策 | 影响 |
|---|---|---|
| ADR-005 | **版本隔离采用按需隔离（三段判定）**，默认 `auto` | M3 必须实现三档选择器 + 判定结果展示 |
| ADR-008 | **元数据全量缓存 + 先缓存后刷新**；缓存 key 用 **MurmurHash2**；多源竞速 | M1 就要落地，否则「≤500ms 可交互」做不到 |
| ADR-009 | **API 前置包版本动态查询，禁止硬编码** | M4 的 `api_for_loader` 必须是 async |
| ADR-003 | **OptiFine 可独立装在纯原版上**；安装走 **Patcher 打补丁**（非文件覆盖），且必须**最后安装** | M4 的 OptiFine 安装要分「Patcher 打补丁」和「Forge 兼容」两条路，并处理 `mods.toml` 删除与 launchwrapper |
| ADR-007 | **实例名预填默认值且永不锁定** | M1.5 的创建表单 |
| ADR-014 | **mods 只备份清单不备份 jar** | M3 备份功能，否则会吃光磁盘 |
| **ADR-013** | **Java 版本约束是 13 条带优先级的规则**，`MODDED_JAVA_*` 只在装了 Forge 时生效 | M6 不能做成「MC 版本 → Java 版本」的查表 |
| **ADR-020** | **加载器识别必须靠 libraries 的 Maven 坐标 + 排除条件**，不能靠文件名 | M4 要处理 Fabric/LegacyFabric、Forge/NeoForge 两组歧义 |
| **ADR-021** | **Mod 兼容性只能「提示」不能「判定」**，措辞为「可能不兼容」 | M5 的徽标降级为黄色，附可点开的推断依据 |
| **ADR-022** | **版本区间用闭区间模型 + 交集运算**（不支持 Maven 半开区间） | M5 依赖冲突检测的数学基础 |
| **ADR-023** | **实例修改采用 Draft 事务机制**（内存快照 → 提交 → 失败逆序回滚） | M3 实例配置改动必须走 Draft，不能直接写盘 |
| **ADR-024** | **整合包导出必须有文件黑名单**（登录凭据绝不入包） | M5 导出功能的安全红线 |
| **ADR-025** | **整合包安装需要 Completion 阶段**（四条 Provider 各一套） | M5 整合包不能只是「解压就完事」 |
| **ADR-026** | **多源竞速与镜像表**；Forge/Fabric/NeoForge 库文件不走原版源 | M1 下载调度层 |
